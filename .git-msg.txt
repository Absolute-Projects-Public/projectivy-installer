Fix an intermittent test failure; name the Fire OS 8 filter fallback

The suite failed about one run in three, on two assertions in the same path. Cause: `grep -q`
piped out of a command exits on the first match, the writer gets EPIPE, and under `pipefail` the
whole pipeline reports failure. Small outputs usually win the race, which is why it was rare.
Every such check now captures the output and matches it with `case`, so there is no pipe to break:
present_pkg, pkg_disabled, the installer's post-install check, the manual-install check, the
accessibility verification, the Home on Fire grant check, the protected-package probe and the
system-app test in the debloat loop. Three consecutive suite runs: 88 passed, 0 failed.

DNS filter on Fire OS 8: no automatable route exists. Backup restore is refused (backup service
disabled), the app folder is hidden from adb, and the app's settings render custom views that
uiautomator cannot read, so driving the UI blind is not something to ship. The tool and the README
now point at dumbtv's own dnsfilter.sh as the reference implementation for that piece, and at
NextDNS as the no-app alternative. That matches what its maintainer found: the 4K Max is "partial".
